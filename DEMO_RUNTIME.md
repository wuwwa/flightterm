# On-demand demo runtime

Private uses the shared traffic feed immediately after wake. A single in-process refresh runs every 15 seconds, processes only a new feed timestamp, and rejects feed snapshots older than five minutes. Current positions can change each feed cycle; SQLite history remains limited to one observation per half-hour slot. Empty feeds and missing registry data never create fabricated zero samples.

The UI identifies recent, saved and unavailable observations by sample age, independently of HTTP success. Comparisons require the same feed/region and cohort version, with no gap greater than 45 minutes. Historical references require 30 qualifying samples over at least seven observed days and remain descriptive of visit-driven coverage, not a population estimate. History is filtered to the current source. Reference calculations are cached per recorded snapshot and half-hour reference slot, and a curve reads its input rows once.

The recorded example contains 12 original observations from 21 August 2026, exported from the existing local SQLite database. Timestamps and positions are unchanged. It is bundled with the lazy-loaded Private workspace, never merged with current observations, and does not offer links that would mix recorded details with live dossiers. Clickable time-and-count tiles select the recorded observation; gap labels preserve missing intervals. A compact bar chart above the tiles shows counts from zero at their actual timestamps, shades gaps over 45 minutes, and never interpolates missing observations. Recorded bars also select their sample, keeping the selected tile in view on narrow screens. The chart reuses existing data and adds no requests. Source attribution is a small footer; field-specific caveats remain on the relevant aircraft details. Map tiles still require connectivity.

Selecting an aircraft loads up to 12 hours of locally stored sightings and Private observations, bounded to the displayed sample. Observed tracks break at coverage gaps and implausible jumps, and reset after a ground observation or a gap over 90 minutes. A recent, active FAA plan matched to the current callsign supplies resolved filed fixes. These form an approximate route, not a complete airway/procedure reconstruction; airport-only routes are labeled destination estimates. Missing, stale, completed or mismatched plans fall back to a separately labeled ten-minute ground-speed/heading projection when those measurements exist. Recorded mode uses only frames at or before the selected time and never fetches current flight plans. Path lookups run only for the selected aircraft in the visible Current view, query local stores, and neither call paid providers nor renew the SWIM worker lease.

Frontend flight requests, enrichment queues and anomaly streams run only in the visible Flights workspace. SWIM polling and wake requests run only while NAS is visible. Private pauses data requests in recorded mode and hidden tabs stop the shared health polling. Reference registry refresh waits two minutes on an existing installation; an empty installation starts registry bootstrap promptly.

## SWIM deployment

The main app still uses Fly proxy autostop with a zero minimum. The worker uses direct private-network traffic, which Fly proxy autostop cannot measure. Its config therefore disables proxy autostop, enables an authenticated snapshot-consumer idle lease, and exits cleanly after 90 seconds without a snapshot request. Feed arrivals and health checks do not renew this lease. An explicit on-failure restart policy allows clean idle exits to remain stopped.

The main app stops requesting worker snapshots five minutes after the last NAS request (existing SWIM_IDLE_TIMEOUT_MS), so a worker normally sleeps within about 6.5–7 minutes after the last NAS activity, or sooner if the main app stops first. Local development does not exit the worker on idle unless SWIM_EXIT_ON_IDLE=true is explicitly set.

Before deploying the worker configuration, verify the main app has its existing SWIM_WAKE_APP, SWIM_WAKE_MACHINE_ID and FLY_MACHINES_TOKEN settings, with access to start that specific worker. SWIM_WORKER_API_SECRET (or SWIM_INTERNAL_SECRET) must match across both services. These changes create no machines, allocate no addresses and change no secrets.

Deploy the main app and worker together, then verify: open NAS from both stopped machines, receive a worker snapshot, leave NAS and close/ hide the browser, confirm both machines stop, and reopen NAS to verify recovery. This live deployment check is separate from local tests; it has not been performed by editing these files.

References: [Fly machine restart policy](https://fly.io/docs/machines/guides-examples/machine-restart-policy/), [Fly autostop and autostart](https://fly.io/docs/launch/autostop-autostart/).
